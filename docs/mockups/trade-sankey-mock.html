Open questions for the owner
  1. Per-country. With a country picked, the card is removed (tick the box above). The brief assumed a per-country split would be an estimate. It would not: Census publishes HS10 by partner, and every HS10 line has exactly one end use, so a per-country Sankey is exact. Cost: no all-partner query at HS10 (the wildcard fails), so one call per partner per year per flow, about 7,400 calls (a few hours for the first fetch; China, the largest, is 0.7 MB and 6 s per year-flow; raw cache under 1 GB, not committed); the output would be small (2,100 chapter-product-use triples per year-flow nationally, far fewer per partner). Build all-countries first and add countries later (the card would then come back for a country), or never?
  2. Colours. The card above uses neutral grey bars. Here bands take the colour of the end they are “many” of: the use they reach (chapter and product picks) or the chapter they start from (use picks), six solid colours plus a neutral “Other”. Keep, or one accent colour for the whole selection?
  3. Exports vs imports. The mock shows imports (bigger and more split). The card follows the Exports / Imports toggle above. Note export “Civilian aircraft, engines & parts” is one heading (8800) in one chapter, so that use reversed is a single band; the exports chapter-85 state is in the picker for comparison.
  4. Grey on chapter and product picks. A use picked now shows only that use: each product is sized to what it sends there, with no “other uses” band. Chapter and product picks still show grey inflows into each use from outside the selection (Phones & network equipment is 79% of telecom equipment; the other 21% is grey), which is how the many-to-one shows there. Keep that, or drop grey everywhere for the same reason?
  5. Grey inflows only above 1%. A use that takes under 1% of the selection (8517 sends $17M to “Other vehicle parts”) is still drawn and labelled, but without its grey inflow, which would otherwise be $138B of unrelated auto parts. OK?
  6. Data size and refresh. All countries: 2 calls per year (450 KB + 1.1 MB, 5–17 s), 34 calls for 2010–2026, plus one concordance file per year and flow (2010–2019 are old .xls, 2020 on .xlsx). Output roughly 50 KB per year-flow, about 1.7 MB for 2010–2026 (≈ 400 KB gzipped), one file per year so the page loads one year at a time. Weekly refresh: the year in progress plus the prior year, 4 calls.
