# Architecture map

A one-page index of where things live: the data layer, the routes, and the
shared components every view is built from. Paths here are verified against the
tree as of the ICE-removals data session (2026-10-06; the data tracks above each have a `/presidency/<section>` page, listed under Routes). When you touch an area, correct
anything that has drifted.

---

## Data layer

The pipeline (`pipeline/`) fetches raw snapshots, validates them, and transforms
them into normalized JSON in `pipeline/output/` (all committed). The app reads
those at build time and joins them into page-shaped data — nothing pre-joined is
stored. See `docs/DATA_CONVENTIONS.md` for the full contract.

**Data-refresh auto-merge.** Every `*-freshness.yml` workflow ends by calling the shared composite action `.github/actions/gate-and-merge`: it checks out the PR commit, runs `pnpm validate` and `pnpm transform` (committing any regenerated `pipeline/output` to the PR branch), then typecheck, lint, tests, `pnpm pipeline:check` and the build, and squash-merges the PR only if all pass. If a step fails the run goes red and the PR stays open for a human (a PR pushed with `GITHUB_TOKEN` does not trigger `ci.yml`, which is why the gate runs the same commands itself). Repo settings needed: Actions may create and approve PRs, and auto-merge is not required (the action merges directly; `main` is unprotected).

Energy raw source: `pipeline/raw/eia/<SERIES_ID>.json` (`pnpm fetch:eia`, EIA API v2, needs `EIA_API_KEY` — `.env.local` locally, a repo secret in Actions; not part of `fetch:all`; pages by `offset` because the API truncates at 5,000 rows without a warning). Weekly `.github/workflows/energy-freshness.yml` applies the materiality rule in `pipeline/fetch/energy-diff.ts` and opens a PR only when it trips; auto-merged only after the CI gate passes. Schemas and the series catalog: `lib/energy-entities.ts` (the display window is `INDICATORS_DISPLAY_START`; no second constant). **Executive order summaries** (`executive_orders.json` `summary`, the line under each order in the page's lists): what the order does, never why. `pnpm summarize:eos` sends each order's full text to Claude, which must lead with the operative provisions (the clauses turning on "shall", "hereby", "is revoked", "is amended", "I direct"), skip the authority recital, purpose/findings and boilerplate, write present tense starting with the action verb ("Defers certain diesel fuel tax payment obligations and provides penalty relief."), stay neutral (no adjectives carried over from the order), and quote the operative clause verbatim. The model is asked for ≤200 characters; `checkEoSummary` keeps a summary only if it is one or two sentences of 30-240 characters (the slack stops a model that writes to its target being rejected for a few characters), does not open with "This order"/"Executive Order"/"The President", the quote is verbatim (words left out marked "...", each piece in the order and in sequence) and itself operative, every number is in the order (as digits or spelled out, "sixty days"), and ≥70% of its word stems are the order's; a rejected answer is retried with the reason (three tries), and an order that still fails stays uncached. The transform re-runs the check against the committed text, so a hand-edited or stale entry is dropped (reported as `summaries.failing_check`). The note strip above every order list (`ListNote`, in all four list views) says once that the summaries are AI-written, whenever the list holds any; rows carry no per-row tag. The Data notes say how they are checked. Phones clamp it to three lines (tap opens). Model choice: Sonnet 5.5 at xhigh, picked after a blind side-by-side with Opus 5.5 (medium, low) and Sonnet 5.5 high on the same 28 orders (it had the fewest rejected answers, at about half Opus's cost). Summaries cover orders signed from 2009-01-20 (Obama onward); the weekly workflow passes `--from 2009-01-20` so it summarises only new orders. Earlier orders have none until `pnpm summarize:eos -- --from 1994-01-01` is run deliberately.

### Justices directory (`components/court/directory/`, `lib/justice-directory*.ts`, `/supreme-court/justices`)

Counting rules (all in `lib/justice-directory.ts`, shown under "Data notes"): **Confirmed** is `senate_vote` on the appointment that seated the justice ("98–0"; null = "Voice", 17 justices, the last in 1965), the first appointment for a justice later made Chief; it sorts by ayes ÷ votes cast, voice votes first (`confirmedShare`). It replaced a majority-opinions column, which mostly tracked years served (`majorityOpinions` stays on the row for the tenure-timeline tooltip). The **dissent rate** is dissenting votes ÷ votes where a side was taken (an equally divided Court or a recusal is neither), as a percentage; both cover argued cases from the 1946 term on, so the nine justices who left before then show "—" for the dissent rate and those seated before 1946 (`VOTES_FROM`) carry a † (partial career). The takeaway compares dissent rates only among justices with 500+ such votes (`MIN_VOTES_FOR_RATE`). **Years served** are decimal years between the first day on the Court and the last (or the build date), completed years printed (Douglas: 36); Hughes's 1916–1930 break is the one `FIRST_STINT_END` entry, drawn as two bar segments and left out of his years. **Bench order** (`benchOrder`) is by `appointment_start` among the sitting associates, most senior to the Chief's right (audience left). The latest and career scores are the Court payload's (`s` at the last term, `career`). Timeline order is chronological by first day, the table's default is newest first (rule 15a); the timeline has no president band (the bar colour is the appointing party). Not built: Wikipedia pageviews (add when the reusable fetcher exists) and Senate confirmation votes by name (a roll-call source would be new; only the tally is shown).

### Page-level layout rules (every page and mock)

1. Intro paragraph and footnotes span the full content width (`max-w-[1180px]` container); no `max-w`/ch caps (`PageHeader` has none on purpose).
2. Top-level nav order is Presidency, Congress, Supreme Court, then the neutral cross-branch Timeline tab (ink underline, no branch colour); the active vertical keeps its underline. Sub-page links (Presidents / Executive orders / Economy / Energy / Immigration / Trade / Foreign aid / Troops abroad) are a separate row.
2a. Every section sub-page's `PageHeader` (an individual president, member or justice page excepted: those have none) passes an `eyebrow` of the form "Section · Page" (e.g. "Congress · Wealth", "Presidency · Trade"), matching the nav. Top-level pages without a section (About, Contact, Methodology, Home) don't use one.
2b. **The page keeps its question; search gets a keyword title** (owner's call, 2026-10-21). A section page's `<h1>` stays its question in Title Case ("How Does Congress Vote?", "What Was the Economy Like?"); its `metadata.title` (the browser tab and search result) is a keyword-led label instead, never the question ("Ideology Scores for Every Member of Congress", "U.S. Economy by President: Jobs, Inflation, Gas"). A topic page's description leads with a headline finding from its own data (`hubDescription` in `lib/hub-seo.ts`, read through the page's loaders, mostly via `lib/og-topics.ts`; built at each deploy, so the weekly freshness merges keep it current; owner's call to keep fast-moving readings like the gas price even though Google's cached snippet can lag): a plain fact or a comparison with the record ("the most since …") or a recent baseline, biased toward recency over the most dramatic change (rule 7c; troops vs 2008, not the 1950s peak), never a cause or grade, naming the president who acted rather than a year's combined total, then what the reader can explore; the static line in the page stays as the fallback. Every page builds its metadata with `pageMetadata()` in `lib/seo.ts`: the title fits 60 characters with " · InsideGov" (a longer one drops the suffix and is cut at a word), the description is one or two sentences under 160 characters (`clampDescription`), and canonical, Open Graph and Twitter fields follow from them. Entity pages use the name people search, in both the title and the H1: a law's popular or short title (`lawShortTitle` in `lib/law-seo.ts`, never "Pub. L." codes in the title; the formal title prints under the H1; a law with a "Who voted for it" chart leads with what only this site has, via `lawSeo`: "<Name>: How Congress Voted (<year>)" and "The <Name> passed the House 224–201 and the Senate 51–48. See how every member voted by ideology, its path through committee and what it does.", naming only the chambers the chart covers; a voice-vote law keeps its plain summary plus "Passed by voice vote; signed by …"), a case's short name (`shortCaseName` in `lib/case-name.ts`, "Astrue v. Capato", Wikipedia's title first; the full caption prints under the H1, never the reporter citation in the title), a justice's description leads with ideology (`justiceSeo`: the directory's voting-lean trajectory, then "the Court's median justice in N terms", else an all-time top-10 rank, else today's bench rank, then then a second sentence in the same voice, "See how <Surname> voted in every case, from landmark rulings to 5–4 splits.", shortening to fit; the appointing president is left out), a member's description leads with where they sit in their caucus in their chamber (`memberSeo` + `memberSeoInput` in `lib/member-seo-data.ts`: top or bottom 5 get a rank, 40th–60th percentile "votes near the middle", else a percentage stated from the side they are on), then "See where <Surname> has stood since <year>, N laws sponsored and a $X net worth"; a president's leads with the record in office (`presidentSeo`: laws signed with the major count, executive orders when the record covers the whole term, justices appointed, then party control of Congress or the page's sections), never economy figures (rule 2c), and a member's or justice's well-known name (`GIVEN_NAME_OVERRIDES` in `lib/display-name.ts`, `JUSTICE_KNOWN_AS` in `lib/court-derive.ts`, matched to their Wikipedia article titles). Descriptions say what the page shows in plain words (no "DW-NOMINATE"/"Martin–Quinn" as the lead) and use "Democratic", never "Democrat", as the adjective.
2g. **Numbers in prose are compact once they reach 10,000** (owner's call, 2026-10-21). In running text, headlines, takeaways, share cards and search descriptions, a figure of 10,000 or more is shortened to one decimal with K, M or B: "166.6K troops", "442.6K removals", "283M barrels", "$1.7M", "$47.8B" (a trailing ".0" dropped; rounded, not truncated; uppercase K/M/B). Below 10,000 it stays exact with commas ("2,464 laws", "225 executive orders"), since "2.5K laws" reads worse than the number. Exact values stay where a reader goes for precision: tables, "View as table", tooltips and pinned readouts. Use `compactNumber` / `compactDollars` in `lib/format-number.ts`; don't add another formatter. (Chart axis ticks and tight phone cells may abbreviate lower, e.g. "1.1k" in a heatmap cell.)
2c. **The "not a cause / not a grade" caveat is said once per place, not on every card.** It lives in the Methodology page, About, a president page's "How to read this" and the Economy intro. Data notes, source lines, tooltips and other page intros do not repeat it (they describe the data only). The one kept exception is the Energy "enabled, not caused" note on a policy flag, which says something specific about that action.
2d. **A person's page header is one layout for presidents, members and justices.** Kicker = the person's role only ("President", "Representative", "Chief Justice"; never a section prefix like "Supreme Court ·" and no "Presidency · Presidents" eyebrow). Portrait and identity on the left (kicker, serif name, party line, dates / service lines), the Wikipedia lead on the right under the label **"About"** (never "Biography"), split by a `--line` left border from `lg`; below `lg` About stacks under the portrait behind a top rule. The president and justice headers use a **500px** identity column from `lg` (`lg:w-[500px]`, so "Donald Trump" and "45th and 47th president · Republican" never wrap); the member header keeps its own 380px column. A president page's previous / next president (surnames only, so the row stays on one line) and "All presidents" sit **under the identity block, above About**, on desktop and phone alike. The credit line is "From Wikipedia (text may be abridged), licensed under CC BY-SA 4.0" on members and presidents (justices still print "Source: Wikipedia, CC BY-SA 4.0").

The group of dropdowns carries `lg:min-w-[…]` sized to its selects' minimums plus captions, and the slider takes what is left. Check a new bar at 1024px.

Phones: two controls per row (a select at half width beside another select, or beside the slider); a full-width control only when it truly needs the room. Adding a filter means making the others narrower first, not adding a row. Terms add up (see "Troops abroad page" for the exact tap rules). 5a. **On phones, a dropdown alone on its row has its label beside it; dropdowns that share a row have no label at all (the one phone exception to rule 5d).** A lone dropdown (Trade Country, Executive orders Topic) would otherwise run the full width of the screen, so its label sits inline to its left, left-aligned (`flex-row items-center gap-2`, the control taking the remaining width, `<FilterCaption phone>`), which also saves a line of height and keeps the label readable. Where two or more filters share a phone row (**a checkbox counts as a filter**: Decisions' Issue area + Landmark cases; Foreign aid's Country + Sector, Troops abroad's Country + Branch, Laws' Policy area + Vote + Sponsor, Wealth, Demographics, the Explorer, Court), **no label is drawn, and none is stacked above the control**: the select's own face ("All sectors", "Any vote") says what it is, and the caption stays in the accessibility tree (`FilterCaption` default, `max-sm:sr-only`). 5c. **A filter whose options are parts of a whole is a checkbox dropdown (`charts/MultiSelectFilter`), not a single-select.** Policy area, Vote, Issue area, Topic, Sector and the committee Policy area / Subcommittee. Reason: one option is often big enough to swamp the rest (Commemorations are 25% of all laws, Peace and security 39% of foreign aid, Government operations 23% of executive orders), so "everything except this" is a real question a single-select cannot ask. The button is the same size as the select it replaces (the panel overlays the page, so the bar stays one line) and reads "All topics", the one option, "All but X" or "3 of 9 topics", with an accent border and an n/N badge while filtered. The panel has All / Clear in its header (so "only X" is Clear, then X: there is no per-row "only"), each row a tick box, a colour swatch **wherever the page's charts colour the options** (Laws, Decisions, Executive orders, Foreign aid: the same token the chart and its legend use, and options that share the neutral "Other" colour wear it; none on the committee card, whose chart does not colour by area) and a count for the years shown, and an optional one-line hint under a row that needs explaining (Laws: Commemorations). There is no "skip X" shortcut button: unticking the row is one click. Not for identity filters with long lists (country, state, president), a single year, a sort order or a form field: those stay single-select or a combobox. **State is `Picked<T>`** (`lib/multi-select.ts`): `null` = everything ticked = no filter (a full set is always stored as `null`), otherwise the set of ticked ids; an empty set (Clear, before the first tick) is allowed and shows nothing with a one-line "tick one" message instead of a chart. Like a time-series filter (rule 4) the charts draw only the ticked options and re-lay-out; comparison charts (rows, heatmap, legends) dim the unticked. **A click on a row, legend entry or heatmap row ticks just that one; a second click clears the filter** (`toggleOnly`). A filter that needs one option (Laws card 3's measure lock, card 2's isolated band, foreign aid's single-sector colour) reads `soleOf(selection)`. A bill, case or law with no value for the filter (a committee bill with no policy area) is its own row where the data has any; Decisions' 67 cases with no issue area count only under "all". **Phones:** the panel is up to the screen width and shifts to stay on screen; Laws moves its "Major laws" checkbox into the Policy area panel's footer (below `sm`, a dot on the button says it is on) so the bar is two controls wide, not three.
5e. **A control's default value is never clipped.** Whatever a select shows at rest ("Any outcome", "All issue areas") must fit in full beside its caption at every width a bar shows it; size the control to its longest default plus the chevron before narrowing it, and give the slider the leftover.
5d. **Every control in a pinned filter bar has a caption on desktop, and one component draws it.** A small mono-caps label (`FilterCaption` in `charts/FilterBarParts`, the `FILTER_LABEL` style) sits to the left of the control from `sm`, so a reader never has to open a dropdown to learn what it filters: Chamber, Show (Members / Committees), State, Party, Sponsor, Policy area, Vote, Issue area, Country, Sector, Branch, Topic, Appointed by, President. **Segmented switches are captioned too** (`ChamberSwitch` draws its own "Chamber"; the Explorer's Members / Committees switch has "Show"; Court's Both / Democratic / Republican pills have "Appointed by"): buttons that name themselves are not a reason to skip it. Only the Years-shown slider and the Court term slider go without (their readout is their label). **Phones: the caption is screen-reader-only** (`FilterCaption`'s default, `max-sm:sr-only`), so two or three controls still share a row; never a phone-only caption (Demographics once had one on Chamber alone; it was removed). The one exception is rule 5a, `<FilterCaption phone>`: a dropdown alone on its phone row keeps its label beside it (Trade Country, Executive orders Topic); filters sharing a row, a checkbox included, get none, not even stacked above (Foreign aid, Troops abroad). Troops abroad's Country / Branch hold their captions back until `lg` (`FilterCaption from="lg"`) because that bar is tight; that is the only place a desktop caption may be dropped, and only below `lg`. **Never write a caption's classes by hand** (no `hidden sm:inline` spans, no local `LABEL` constants): use `FilterCaption`. **Party is `charts/PartyFilter`**, which carries its own caption and takes the page's option names ("Democrats"; "Sponsor" on Laws, where the party is the bill's sponsor's, with the select named "Sponsor party" for screen readers): use it for any page that gains a party pick (Demographics, Wealth, Laws) rather than a bare `<select>`. A party pick **filters** time series and lists and **dims** comparison charts and scatters (rule 4). **A bar with room for one fewer control moves the least-used one into a dropdown panel**: Laws' "Major laws" checkbox sits in the Policy area panel's footer below `xl` (and on phones), with a dot on the button while it is on (`MultiSelectFilter` `footer` / `dotClassName`), so the slider keeps about 270px at 1024px.
6. **Numbered labels on a chart tap-to-pin.** Any numbered marker placed *on the chart's own axis* (definition-change notes, tariff event flags) opens its note on tap/click and keeps it open until the next tap elsewhere, Esc, or scroll; hover (mouse only) previews it. Tapping a different number switches; tapping the same one closes. The note carries the full text, so there is **no numbered key printed under the chart**. References: `immigration/RemovalsChart` (`data-ice-hit`), `trade/TradeTariffChart` (`data-flag-hit`). Numbered markers are for annotations tied to a position on the chart; explanatory text that is not (what a count means, coverage, definitions) is never a marker: it goes in that chart's Data notes (rule 7), as in `immigration/RemovalsCountryCard`.
6a. **Tapping a bar keeps its tooltip open (every per-year bar chart).** On a phone a tap opens the bar's tooltip and **it stays open after the finger lifts**; it closes on a tap outside the chart, Esc, a page scroll, or a second tap on the same bar. Tapping a different bar moves it, and dragging across bars scrubs it. A mouse is unchanged (follows the pointer, closes on leave). Don't rely on hover or a long press for touch. Implementation: `useStickyTooltip` in `charts/Tooltip` (a browser fires `pointerleave` right after `pointerup`, which used to hide a plain `useTooltip` at once; the hook ignores leave for touch and pen), plus `data-sticky-tip` on the chart wrapper so a tap inside it is not an "outside" tap. Wire `down` / `moved` / `up` for the tap-the-same-bar close. References: `charts/StackedBars` (executive orders), `foreign-aid/SpendingChart`, `troops/TroopsChart`; `immigration/RemovalsChart` does the same with its own pinned card (`data-ice-hit`). **Any new bar chart uses `useStickyTooltip`**; scatters keep rule 10e's pinned card.
6c. **A hover tooltip and a note card are never on screen together.** Where a chart has both bar tooltips and numbered-note cards (`open` keyed `b<year>` for a bar, another letter for a note), the `Tooltip` state is passed only while a *bar* is the open item: `state={open && !open.pinned && open.key.startsWith("b") ? tip.state : null}`. Passing it whenever `open` is an unpinned item leaves the last bar's stale tooltip showing over a note opened by hovering a marker. Every immigration bar chart (`RemovalsChart`, `RefugeeChart`, `LprChart`, `EncountersChart`) follows this; a new one does too.
6b. **One tooltip shape, and nothing hand-positions it.** Every hover tooltip is the shared `charts/Tooltip` (a dark card that measures itself and clamps inside the viewport, so numbers can never run off an edge), never a hand-placed box with a fixed pixel width or `whitespace-nowrap`. Its content is `charts/TipCard`: the label on the left and the headline value on the right (`FY2008` … `1,107,126`), one muted `tt-mono` line under it (who, dates, and "· Preliminary" only when the year is not final: never print "Final"), then rows of swatch / name / right-aligned mono value in stack order (top segment first), then any separate figure (a ceiling, a detention count) under its own rule. The box sizes to its widest row (`tt-wide`). Don't put the unit in the header (the card's toggle or title already says "green cards"), don't add hints about things the tooltip cannot do ("Select for detail": a hover tooltip is never selectable; only a pinned card, rule 10e, may carry an action line), and don't hand-roll swatches. **Detail cards are different from tooltips:** a tapped or keyboard-opened bar, and the numbered-note and rule cards, are in-chart cards (`immigration/Cards`, `RefugeeCards`, `LprCards`) that can hold a source link or long prose; they are positioned by the chart and are the only place a fixed width is allowed. A hover never shows them, and showing one hides the tooltip. References: `immigration/LprChart` (`LprYearTip`), `foreign-aid/SpendingChart`.
6d. **A source or method change is a line, not text on the plot.** Where a series changes source or method (the tariff chart's 2010 USITC-to-Census switch, the mortgage card's Nov 2022 Freddie Mac survey change), draw a muted dashed vertical line, key it in the legend ("Data source change, Jan 2010"), and explain it in the chart's Data notes. Never print source or method names inside the plot: they read as data, crowd peak/low labels, and are methodology (rule 7). Numbered definition-change markers (rule 6) are unaffected.

7a. **A member's name carries their photo only in a member row.** Where a list row or table row is about one member, a small `MemberFace` (`components/MemberPhoto.tsx`, 20×24px) sits before the name, the way a committee carries its seal; the row stays on one line and the neighbouring column absorbs the width. Members named inline (a header's sponsor and cosponsors, an amendment's sponsor, running text) get no photo, a current member with no committed photo gets the grey silhouette (so names stay aligned), and a former member gets their small photo when the source has one (`former` in `member-photos.json`), otherwise nothing. Member tooltips on charts show the larger `MemberPhoto` with `tt-photo`.
7. **Chart explanations live under "Data notes".** Footnote-style text under a chart (sources, "terms/band under the axis", "Not on the map", methodology) goes in `components/MethodologyNote` (label "Data notes": collapsed by default at every width), never as loose paragraphs. **Keep each Data notes to one short paragraph (about 60–100 words):** what the numbers count, the one or two caveats a reader could misread, and the source; leave out anything the page's "How to read this" or another chart's note already says (the term band, partial periods, shared definitions: say it once, at the highest level it applies), leave out how-to-use-the-chart instructions (the legend, toggles and tooltips explain themselves) and detail that only matters to a specialist. Legends stay visible; only explanatory prose collapses. Used under every chart card, including executive orders and foreign aid. **Source notes are different:** the page-level "Source: …" paragraph at the bottom of a page is plain, always-visible text (`m-0 text-[0.8rem] leading-[1.6] text-ink-muted`), never collapsible. All methodology prose for a chart (including what used to sit in a page footer) is folded into that chart's one "Data notes", so a page has one Data notes per chart and one open Source line, not both at the bottom. **Pages carry no "How to read this" disclosure at the top, except Trade and Decisions (the 12 topic descriptions from `pipeline/reference/decision-groups.json`)** (`components/HowToRead`, collapsed, inside `PageHeader` after the intro; the owner removed the rest, so don't add one to a new page without being asked). Caveats about a page's numbers go in the relevant chart's Data notes and the Source line. The Source line(s) (and any required attribution, e.g. the FRED notice) are plain open paragraphs at the bottom of the page, with no card and no heading ("About these numbers" is not a pattern). No `max-w`, no border or `footer` chrome, `text-ink-muted` (not `ink-faint`) on every page, Court and Congress included. Per-chart notes (the grey text under a chart, e.g. the Martin–Quinn scale note on the Court cards) are Data notes too, never loose grey paragraphs. References: `economy/EconomyPageClient`, `wealth/WealthPageClient`. **Long lists scroll inside a fixed-height box** (rule 11a), at every width (exception: a short list that is fully legible, such as the 13 topic rows on the Decisions page, scrolls only on phones and shows in full from `lg`, because a box that hides one or two rows is worse than none): the executive-order list is a `max-h-[32rem]` box with `overscroll-contain touch-scroll`, not a "show more" button and not an auto-expanding list. **Gotcha:** any scroll box that contains `sr-only` text (it is `position:absolute`) must itself be `relative`, otherwise those spans escape the box, stay positioned against the page, and stretch the document to thousands of pixels: the "infinite scroll" bug seen on the executive-order list. `MethodologyNote` (a client component) ends every note with a muted "Report a correction" link to `/contact?topic=correction&page=<usePathname()>`, so no page passes anything.
7b. **Sources are linked inside the note.** Every source a Data note or page "Source: …" line names (GovInfo Bill Status, State Department, the Presidential Determinations on Refugee Admissions, Census Bureau, …) is a link to the page or document it came from, on the words the note already prints, never a rewording. Use `components/SourceLink` (underline with `underline-offset-2`, `hover:text-ink`, like "Report a correction"; opens in a new tab with `rel="noreferrer"`), with `id` from `lib/source-links.ts` (the one place a source's address is written; reuse addresses the repo already records: `pipeline/reference/*-catalog.json`, `docs/*_SOURCE_NOTES.md`, `lib/methodology-content.ts`) or `href` for an address that comes from the data itself (`year.sourceUrl`). Link the first mention of a source in a note, not every one. Verify a new address resolves before adding it. A new note that names a source without a link, or a new source with no entry in `lib/source-links.ts`, is unfinished.
7a. **"Data notes" and "View as table" share one line under a chart.** Wrap the card's `MethodologyNote` and its table fallback (both `<details>`) in `components/charts/ChartNotesRow` (`flex flex-wrap`, `gap-x-4`): the two summaries sit side by side, Data notes first, and whichever is open takes the full width and wraps beneath the other. Spacing is deliberately tight: `mt-2` above the row (`NOTES_ROW`) and above each `<details>`, `mt-1` between a summary and its open text, `mt-3` between a chart and the row on energy cards; do not add padding above or below Data notes. Never stack them as separate full-width rows; a card with only one of the two just uses its own disclosure. On a paired-card grid the row is pinned to the card bottom (rule 10r). Reference: `economy/EconomyCard`, `immigration/RemovalsCard`.
7c. **A chart's line under its title is a takeaway: what the chart shows, in one or two sentences.** Readers said the charts were hard to read without being told what to look at, so the muted description under a card title ("Share of the labor force without a job, seasonally adjusted") is replaced by a takeaway in ink (`text-ink`, 0.875rem; 0.95rem on a hero card), and that definition moves into the first sentence of the card's Data notes (rule 7). Writing rules: **at most two sentences and about 25–45 words; say what the chart shows, never why** (no causes, no "thanks to", no "soared" or "plunged"; a president is named only as a fact about who signed or who was in office); **anchor on peaks, records, troughs and turning points, each with its date**, so the sentence stays true when new data arrives; **and favour recency over drama** (owner's call, 2026-10-21; it applies to every narrative: takeaways, context lines, ledes, share-card captions and search descriptions, existing and new): pick the most recent anchor that still makes the point ("down from 364,202 in 2008", "the most since fiscal 2013", "from 2015 through 2025") over the most dramatic one decades back ("down from 1.1 million in 1953"); an old record earns its place only when it is still the defining fact of the chart, and then it comes after a recent anchor, not instead of it; leave the latest value to the card's readout; bound any "recent" claim with an end date ("From 2020 through 2025", "by early 2026"), never "since 2020" or "still". The takeaway describes the chart's full default window; it is not rewritten when the year slider narrows the view. **Every figure a takeaway cites is checked against `pipeline/output/` in a test** (`lib/economy-takeaways.test.ts`): a data refresh or revision that makes a sentence untrue fails CI, and the fix is to rewrite the sentence, then the check. Facts from before a chart's data starts ("the highest since records began in 1948") can't be checked there and must be ones a reader could verify from the source. Reference: Economy (`economy/specs.ts` `takeaway`, `economy/EconomyCard`); Executive orders (`executive-orders/takeaways.ts`, checked in `lib/executive-orders-takeaways.test.ts`; `ChartCard`'s `takeaway` prop draws it in ink in place of the muted `lede`). Every section page now follows this rule (Presidency: Economy, Energy, Executive orders, Immigration, Trade, Foreign aid, Troops abroad; Congress: Ideology, Wealth, Demographics, Laws; Supreme Court: Ideology, Decisions), each with its own `lib/<page>-takeaways.test.ts`. Member, committee, law and justice pages don't have takeaways yet.
7d. **A context line can sit behind the takeaway, naming the political events behind what the chart shows. It is never a Data note.** Readers asked why a highlight happened; the takeaway stays what-not-why (rule 7c), and the "why" goes in a context line, closed by default behind a small "i Context" pill at the end of the takeaway that opens a muted panel under it (`text-ink-muted`, 0.8rem, starting "Context:", the sources named in brackets). **Use** `useTakeawayContext(takeaway, context)` from `charts/ContextLine` (pass the returned `takeaway` to the card's `takeaway` prop and render `panel` as the card's first child); `context` is a `ContextEntry` (`lib/chart-context.ts`: `text`, plus `sources`, each a `SourceLink` id from `lib/source-links.ts` and a short label). Without an entry the takeaway renders as before. **Every context line names at least one dated political event** behind what the chart shows, linked to its source: an election or change of party control; an appointment, confirmation or departure; a statute; an executive order, proclamation, Presidential Determination or agency rule; a court ruling; an appropriations or budget action; a shutdown. It then says how the chart lines up with that event, and where an agency's own report ties the change to it, gives that as the agency's ("DHS attributes…", "CBP said…"), never in the page's voice. **What a context line is not:** how a number is measured or estimated, what a source counts or leaves out, a change in counting or method, or a market, technology or economic fact with no political event in it (a recession's dates, a shale boom). Those go in the card's Data notes (rule 7) or nowhere. If a card has no political event behind its highlight, it has no context line. **Every context line says why its event matters for what the reader sees:** it names the feature on the chart the event lines up with (a drop, a peak, a gap, a record) and, where the law or the record itself states it, the mechanism ("an eight-justice Court can't split 5–4"; "the Act ended most mandatory appeals"). A dated event with no link to the chart is not context. Prefer the events behind the chart's main pattern to a one-year oddity; a line about a single year must explain why that year looks the way it does. **Lean toward recent events, but don't cut history that matters.** Most readers know the last decade or so, so when the choice is between an older line that is weak (a one-year oddity, or a data note at best) and a recent political event that ties to something on the chart, use the recent one. An older event stays when it really explains what the chart shows: the law behind a series' main shift, the war behind its biggest peak, the realignment behind a long trend. Ten years is a lean, not a cutoff. **No context states a cause for a contested, multi-factor change** (conditions abroad, the economy, how much a policy moved crossings or removals): say when a dated action took effect next to what the chart did, for every administration alike, and stop there; no "because", "due to", "led to" or "drove". Timing is allowed ("fell by half or more within two months of each entry proclamation"); attribution is not. At most two sentences and 45 words, counts in short form (207.1k, 1.8M) like the takeaway. Many cards need none. **Every figure in a context line is tested like the takeaway's** against `pipeline/output/`; a fact from a cited document outside the pipeline is pinned to the phrase the line uses, and each source id must resolve. Reference: Immigration (`immigration/takeaways.ts` `IMMIGRATION_CONTEXT` and `contextFor`, checked in `lib/immigration-takeaways.test.ts`). Dated policy markers on the encounters and removals charts were proposed for the contested causes but are **not built**; the draft and its selection test are in `docs/immigration-policy-markers-draft.md`.
8. **Colour: solid colours only.** Categorical series are one solid colour each (`--topic-<topic>`, `--sector-*`, `--fuel-*`, party tokens). The seven `--fuel-*` electricity colours are validated pairwise (`validate_palette.js`); the oil card reuses five `--sector-*` tokens for its five lines. No hatch or dot patterns to tell series apart (they read as noise on phones); the one exception is the diagonal hatch that marks a *partial year*, which is a status, not a series. Colour is never the only cue: name the series in the legend and tooltip.
9. **Maps, scatterplots and any chart that plots data on a grid zoom and pan.** "On a grid" means points or lines placed by two continuous axes: choropleth/point maps, scatterplots and compasses (`senate/CompassChart`, `committee/CommitteeCompass`, `trade/TradeScatterCard`, `wealth/NetWorthScatterCard`) and continuous-axis line charts such as the Court's "How each justice moved" ideology chart (`court/JusticeOverTimeChart`). Ordinary per-category/per-slot bar, stacked-bar, area and simple per-year line charts do not need it (they use the Years-shown slider instead). A new grid chart ships with zoom/pan from day one, never as a follow-up. Use `charts/use-zoom-pan` + `charts/ZoomControls` (+/−/reset corner buttons, double-click, pinch, Ctrl/⌘ + wheel, drag to pan; plain wheel still scrolls the page; touch drag pans only once zoomed, so the page still scrolls at full view). For an SVG map the hook runs on a normalized `[-1, 1]` domain (`extent: 1`) and drives the `viewBox`; borders use `vectorEffect: non-scaling-stroke` and point markers shrink with zoom so they stay legible. Reference: `foreign-aid/MapCard`, scatters in `trade/TradeScatterCard`.
9a. **Choropleths name their top three.** Every map (`trade/TradeMap`, `foreign-aid/MapCard`, `immigration/RemovalsMap`) draws a dot, a short leader line and a "Name value" label for the three leading countries on the measure shown (`charts/MapCallouts`): constant 11px text at any zoom, placed in screen pixels so a label that would hit another or leave the visible map tries another offset and is dropped only if none fit, none for a country outside the zoomed window. Three, not five: more reads as clutter. Anchors are the middle of each outline's largest piece.
10. **Labels never vanish.** If a label doesn't fit horizontally, shorten it (code), shrink it, or rotate it; a blank box is a bug. Phones may use taller spans to fit rotated names. **Run/span labels (the "Who's been No. 1" / "Who's hosted the most" cards) try the full name across the span, then the code, then slant the name (or the code, if the name is long) up and to the right at any width, never leaving the span unlabelled; the label band grows to 46px only when a slanted label is present.** Term-band president labels fall back to a four-letter abbreviation ("Eise.") instead of disappearing. Reference: `foreign-aid/FirstPlaceCard`, `troops/TroopsFirstPlaceCard` (`labelFor`), `troops/TroopsChart` (term band).
10a. **Y-axis labels sit in a gutter to the left of the plot, never inside it.** Left-axis tick labels are right-aligned at `x = -6` from the plot's left edge and centred on their gridline (`charts/Axis` does this for every `Axis`-based chart; the hand-drawn Economy/Trade/Tariff charts do the same), so bars, lines and dots never run under a label and the bars get clean room. Every chart sets its left margin from `lib/chart-bars`: `yGutter(labels)` (widest label x 6.7px + 10) when its ticks are known up front (foreign aid, troops, Economy, Trade balance/tariff), else the fixed `Y_GUTTER` (five characters: `−0.5`, `$30B`, `100%`); charts with a rotated y caption add 14-22px for it (`Y_GUTTER + 20`). Do not draw tick labels inside the plot again (this replaces the old inside-the-plot rule and its `yLabelInset` workaround, now deleted). Rotated y captions need ~20px beyond the gutter; StackedBars prints its y label horizontally above the plot.
10c. **Every term band shortens its labels the same way.** `lib/term-label.ts` (`fitTermLabel`, `termLabelCandidates`): last name, four letters ("Obam."), initials ("BO"), last initial, never dropped. Only the two Bushes carry an ordinal ("Bush 41"), and only where room allows; nobody else does. Slider band, `TermBandSvg`, Economy, Trade, Immigration, Troops and Foreign aid all use it; new bands must too.
10b. **Presidential-term bands look like the foreign-aid one.** Every band that marks administrations under a chart (foreign aid `SpendingChart`, executive orders via `charts/StackedBars` `bands`, Economy `EconomyChart`, Trade `EraLayers`, immigration `RemovalsChart`, and the line-chart social-post card in `pipeline/insights/chart.tsx`) is a light tint of the party colour (`color-mix(in oklab, var(--rep|--dem) 20%, var(--surface))`, `rx` 2), a solid 2.5px party-colour rule along its top edge, and a regular-weight `var(--ink)` label. Not a solid party-colour block with white text. The House/Senate majority rows on Economy and Trade are a different layer and keep solid fills. **Any new chart with presidential terms under it must use this style**; there is no other.
10k. **Chart captions pick the wording that fits.** A caption above a panel (the energy cards' second-panel captions, units lines) is given as a list, longest wording first, and the chart draws the first one that fits the plot width (6px a character), so a phone gets "Net imports, million b/d" rather than a cut-off sentence (rule 10). The long explanation moves to the card's Data notes. Reference: `energy/EnergyChart` (`Panel.caption`).
10l. **Preliminary data is a hatched band, named in the tooltip.** Where a series carries a `status`, the stretch that is still preliminary is a diagonal-hatch band across the plot (`ink` lines behind a line chart; `surface` lines drawn over a filled stack, `Panel.hatchOnTop`), a "Preliminary, may be revised" legend item, and the status named in the tooltip and table. It is a status, not a series (rule 8). Reference: `energy/EnergyChart`.
10m. **A flag for a delayed effect says "enabled, not caused."** Any marked action whose effect, if any, arrives years later (`lagged_effect: true`: crude-export repeal, LNG decisions, energy tax credits) carries that sentence in its note, and the page copy says conditions during a presidency are not attributions of cause. Flags name their authority (Executive, Congress, Agency, Court); SPR rows also say what happened to the oil. Flags that merge on a narrow chart list every action they hold. Reference: `energy/EnergyChart` (`FlagNote`), `lib/energy-derive.ts` (`LAGGED_NOTE`).
10n. **A slot that spans two years labels by its opening year and keeps its own tick rhythm.** `StackedBars` / `StackedArea` take `slotYears` (a Congress = 2): year labels fall every `ceil(every / slotYears)` slots from the first (1973, 1983, …), not on round years (a Congress opens in an odd year, so a round-year rule would label nothing). A slot still in progress is hatched (rule 10l) via `partialKeys` and is never the peak or the low. House / Senate majority strips go under the president band only when the page's own checkbox is ticked (default off), one cell per slot, coloured by who held the chamber for most days of the Congress (`controlByCongress`).
10o. **Per-year bars close up as the window gets dense: a bar is 72–80% of its slot, never a fixed pixel gap.** Every per-year bar chart sizes its bar as a share of its slot (`charts/StackedBars` 78%, the troops and foreign-aid spending charts 72%, the "first place" cards 72% (3–40px), the executive-orders hub 80%), so a long window on a phone (46 fiscal years at ~7px a slot) reads as a near-solid run of bars with about a pixel between them, not thin bars in wide empty gaps. The Immigration charts (`slotLayout` in `lib/immigration-chart.ts`) use a 5px gap in a wide slot that shrinks to a seventh of the slot (at least 1px) as it narrows, which lands in the same place. A new per-year bar chart follows one of these and never a fixed gap. Pair it with sparser year labels in a dense window (`yearLabelMode`: every 4th, then every 8th year).
10j. **Every per-year bar chart carries the presidential-term band under its axis, including the run/span cards.** "Who's been No. 1" (`foreign-aid/FirstPlaceCard`) and "Who's hosted the most" (`troops/TroopsFirstPlaceCard`) draw the band under their year axis with `charts/TermBandSvg` (`termSegments` turns per-slot terms into runs; `TERM_BAND_H` is added to the chart height). Same style as rule 10b, labels centred in the segment and shortened rather than dropped (last name, four letters, initials, last initial; rule 10). **Any new chart with one slot per year and a year axis, in this "span labels over bars" style or any other, must include it**, and a page that filters to a year window must pass the window's terms. `TermBandSvg` is the shared drawing for slot-based SVG charts; the older bands in `foreign-aid/SpendingChart` and `troops/TroopsChart` are still their own copies (with their own label placement), made tappable with `PressableBand` + `termPress` (rule 10v), and should move to `TermBandSvg` when next touched.
10v. **A band under a chart is tappable, and it is the filter bar's term band.** Tapping a president's segment under any chart with a year window edits that window exactly as the term band under the filter bar's slider does (`lib/term-window.ts` `toggleTermWindow`, shared by both): an unselected term is added (with any terms between), a selected term at either end of the run is dropped, the only selected term clears the filter back to the full range, a selected term in the middle does nothing. Selected segments take the 34% tint (the others 20%) and, once any is selected, the rest fade to 40%. Slot charts pass `select` to `charts/TermBandSvg` (`TermBandSelect`: the page's `min`/`max`/`value`/`onChange`, `axis(slot, edge)` for the slot's year, and `extent(id)` when the filter bar's band has its own extents so the two agree), `StackedBars` / `StackedArea` forward it as `termSelect`, and `StackedBars`' older `bands` take `bandSelect`; a continuous axis (the Court's "How each justice moved") passes it to `TermSpanSvg`, where the window is the card's own zoom slider. Pages hand the window to deep charts through a small context (`components/demographics/TermWindowContext`, `components/immigration/TermWindowContext`, `useLawsTermSelect`, `useDecisionsTermSelect`) or the page's existing state hook. **Any new chart with a president band under it, on a page or card that has a window (slider or zoom), must make the band tappable the same way** (own-drawn bands use `PressableBand` + `termPress`); a band that only labels is wrong. Bands are `role="button"` groups (`PressableBand`) and the focus ring is for a keyboard with a real pointer only (`.term-band` in `app/globals.css`): phone browsers match `:focus-visible` after a tap and drew a thick outline round the band just picked, so there is none on touch. **A tapped band also offers the president's page.** Every `PressableBand` press, besides editing the window, pins a small card (`charts/BandLink` `useBandLink`: the shared pinned `Tooltip` + `TipCard`, the name and "Open president page →"); the card is the link (rule 10e), and it closes on a press elsewhere, Esc, scroll, a second press on the band, or another band opening its own. The president comes from `PressableBand`'s `president` prop (`TermBandSvg`/`TermSpanSvg` pass the segment's full name; `StackedBars` bands carry `StackBand.president`), else the label's "Name: tap to …" prefix, and resolves through `lib/president-url.ts` `presidentPathByName`; presidents without a page (Roosevelt) get no card. The filter bar's `charts/TermBand` (drag to add a run) does not offer it.
10f. **Stacked bars: segments carry their values when they fit.** `lib/chart-bars.ts` is shared by every stacked-bar chart (`charts/StackedBars`, `troops/TroopsChart`, `foreign-aid/SpendingChart`); its `yGutter` also sizes the y-label gutter (rule 10a). `segmentLabelFits` + `SEGMENT_LABEL_STYLE` print each segment's value inside it only when the segment is at least 15px tall and wide enough for the text, so labels appear as the chart gets wider or the year window narrower.
10d. **Axes fit the data; nothing is pinned to an edge.** Don't cap an axis at an arbitrary round number and draw outliers as clipped markers. The people at the extremes are usually the interesting ones. Size the domain from the data being shown (a round step that holds the largest value, recomputed when a filter changes the set), and keep the middle readable with zoom and ticks instead. Reference: `wealth/NetWorthScatterCard` (`scatterCap`). The trade scatter's pinned triangles are the one remaining exception: its +1,000% cap is stated and its true values are in the tooltip.
10c. **Dropdowns draw their own caret.** `select:not([multiple])` in `app/globals.css` (unlayered, so it beats per-select padding utilities) hides the native caret and paints an inset one (`right 0.55rem`, 1.5rem right padding, colour follows `--ink-muted` in light and dark). Don't add `pr-*`/`appearance` to a select, and size fixed-width ones for the extra padding ("All presidents" needs about 7.75rem).
10e2. **A committee-page compass windows each axis on its own committees.** `CommitteeCompass` `fitToCluster` passes `xDomain`/`yDomain` to `charts/ScatterPlot` (padded extent that always holds the zero-lines, so nothing is clipped) and a shorter 380-unit plot, with `committee/CommitteeNeighborList` under it: a scroll box (`max-h-[11rem]`) that follows the All / Nearest-neighbors toggle (closest first, with chair and ranking member).
10e3. **Compass cards carry a searchable list under the plot; member-page cards share a height.** `profile/MemberNeighborList` and `committee/CommitteeNeighborList` are the same scroll box (`max-h-[11rem]`): All mode is A–Z (members by last name, no rank numbers), Nearest-neighbors mode is closest first and numbered. A small `components/ListSearch` on the right of the grey header line filters by name in both modes. On a member page the compass card and the two right-hand cards stretch to the same height (`items-stretch`, last right card `lg:flex-1`); never let them diverge.
10e4. **HARD RULE: cards that share a row on desktop never leave blank space.** On a member page the compass card and the right-hand cards end at the same pixel, and no card has empty area under its content. How: the row is `items-stretch`; the compass plot is shortened (`height={320}`) so the left card is no taller than the right column; the left card's list box takes whatever height remains (`flex-1`, min 7.5rem, scrolls, so it shows as many rows as fit); the last right card is a flex column whose chart `fill`s it (`BeeswarmChart` / `DelegationChart` `fill`: the plot grows, dots stay centred, gridlines run full height). Any new card placed beside another must either fill like this or be the one that sets the height. Check by comparing `getBoundingClientRect().bottom` of the cards and of the last chart at 1400px for a House member with a big delegation (Pelosi), a small one (Cole) and a senator.
10r. **A two-column chart grid never leaves a lone card.** Add cards in pairs that read naturally side by side, or make one full width. Where a grid's pairs carry a theme, a quiet row label (eyebrow style, muted, label only, plain words) names it. Paired chart cards share row tracks (subgrid), so plots and axes line up across the pair. Reference: Economy (`EconomyPageClient` `CARD_ROWS`, `EconomyCard`): a label `<h2>` with a hairline rule above each pair, each card `md:row-span-5 md:grid-rows-subgrid` (header + reading, description, plot, legend, notes row), the Data notes / View as table row pinned to the bottom of its track, a one- or two-sentence takeaway under each title (rule 7c) with definitions and caveats in Data notes.
10s. **A card's description sits 8px above its bold value or chart.** The gap between a card's intro line (the description under the title) and whatever comes next, usually the headline value or pinned readout, is `mb-2` / `mt-2` (8px), not 12-16px: the value's weight and colour already set it apart from the muted description, so more space only pushes the chart down. `charts/ChartCard` has one lede margin (`mb-2`; the old `tight` prop is gone, every card is tight), and `charts/ToggleReadout` and `charts/PinReadout` open with `mt-2`. Cards with their own header (`economy/EconomyCard`, the energy and trade cards) keep `mt-2` between title and description. A new card uses `ChartCard` or those readouts rather than its own margins.
10e. **Every scatter plot: a dot pins its card; the card is the link or action.** This is the rule for all scatters (the member and committee compasses via `charts/ScatterPlot`, `wealth/NetWorthScatterCard`, `trade/TradeScatterCard`, and any future one). Clicking or tapping a dot never navigates or filters by itself: it pins that dot's tooltip (`usePinnedTooltip` + `<Tooltip onActivate activateHint>` in `charts/Tooltip`, class `.chart-tooltip.is-pinned`, `data-pinned-tooltip`), which takes the pointer and carries its action line ("Open profile →", "Open committee →", "Show in the charts above →"). Clicking the card does the thing. Click the dot again, click elsewhere, or press Esc to unpin. Hover still shows the plain follow-the-pointer tooltip. Phones tap straight to the pinned card too (no hover preview, a larger hit target); the trade scatter no longer has a separate card below the chart. Don't link or filter from the dot itself.
10t. **Every mark that is one named individual works the same way: tap or click opens the card and keeps it open; only the card links to the profile.** This is rule 10e generalised from scatters to every chart (lines, dots, strips, swarms, bench seats). A mouse previews the follow-the-pointer tooltip on hover; a click or tap **pins** that individual's card and it stays until the reader clicks or taps elsewhere, presses Esc, or taps the same mark again (never press-and-hold, never closes on finger-up). The pinned card carries the "Open profile →" line and is the only thing that navigates; a mark never routes on its own, and a mark with no profile page (a former member, the page's own subject) still pins a card, just without the link line. Phones skip the hover preview, so the first tap goes straight to the pinned card. Implementation: `useDotCard` + `<DotCardTooltips card onActivate canActivate>` in `charts/Tooltip` (spread `card.bind(datum)` on the hit target; `card.onKey(datum)` for Enter/Space on a focusable mark; give hit targets a wide invisible stroke on thin lines). Charts that go through `ScatterPlot` or `SwarmRows` get it for free (SwarmRows points keep `onClick` as the card's action, not the dot's). References: `court/JusticeOverTimeChart` (peer lines), `court/JusticeSwarm`, `court/JusticeStrip`, `decisions/detail/BenchCard`, `senate/BeeswarmChart`, `charts/SwarmRows` (state delegations, committee rosters, justices by president); `court/JusticeTrajectory` and `charts/ScatterPlot` use the older `usePinnedTooltip` form of the same behaviour. **Any new chart that draws individuals uses this; don't link, filter or select from the mark itself.** Marks that are not individuals (years, countries, bars) keep rule 6a.
10u. **Every pill on a case is one size and sits in one row.** Outcome (Liberal / Conservative), Landmark, Overruled precedent, Struck down and a justice's vote (Majority / Dissent) all use `components/decisions/pill.ts` (`PILL`, `PILL_NEUTRAL`); only colour differs. On a phone they follow the issue area on the same line while they fit and wrap below it when they do not (outcome, then Landmark, then the justice's vote); the 5–4 count sits at the date's height on the right, so the area line can use the full width. "Landmark" and the topic it concerned are one pill (`PILL_LANDMARK`: the word in the accent colour, the topic after it, never a separate pill that floats free of the word); its words wrap inside the pill rather than being cut off. A case list's scroll box never scrolls sideways (`overflow-x-hidden`); nothing in a row is wider than the card. From `sm` the outcome and Landmark pills sit inline after the case name and the justice's vote keeps its own column. The outcome pill's explanatory note still opens on hover, focus or tap. Reference: `decisions/CaseListCard` (`CaseRow`), `decisions/detail/DecisionPageView` (`Facts`).
10g. **Every chart legend is one size: `LEGEND_ROW` + `LEGEND_ITEM`, no exceptions.** All legends use `charts/legend` (`LEGEND_ROW`: 0.7rem type, `leading-tight`, `gap-x-2.5 gap-y-1`; `LEGEND_ITEM`: swatch + text, `gap-1`, `whitespace-nowrap`, 10px swatch; `LegendToggle` entries match), so a legend fills one line wherever it can and wraps between items, never inside one. **Never write a legend's type size, gap or swatch size by hand** (not 0.72, 0.75 or 0.8rem, not `gap-x-4` or `gap-x-5`, not a 12px swatch or a bordered chip): the whole site was swept onto these classes (economy, trade, energy, wealth, court, senate, laws, decisions, committees, immigration, foreign aid, troops, executive orders), and a new chart's legend starts from them. A legend that is also a control (executive-order topics, class and region filters) is a row of `LegendToggle` entries, not a row of buttons or chips. Compass-style legends with a count (`senate/Legend`, `CommitteeChamberLegend`) keep their border-top and padding but use the same row and a 10px dot. Shorten legend text rather than let it wrap (`All other (4 sectors)` is `Other (4 sectors)`, the long region name has a `short` form in `lib/troops-regions.ts` `regionLegendLabel`, the Iraq/Afghanistan entry is "In/around Iraq & Afghanistan (DMDC; not in bars)"). **On phones a legend that would run past two lines is capped at two lines and scrolls sideways** (`LEGEND_ROW_CAPPED`: a two-row grid flowing by column below `sm`, the ordinary wrapping row from `sm`); the Immigration charts and the executive-order topic key use it.
10h. **Year axes show a few years, not all.** A year axis labels every `n`th year with `n` from `yearLabelEvery(step)` (1, 2, 5, 10 or 20) so labels sit about 46px apart: on a phone a 74-bar chart shows 1960, 1980, 2000, 2020, and a zoomed window shows every year. Never print every year and let the digits overlap. Reference: `troops/TroopsChart`, `troops/TroopsFirstPlaceCard`.
10i. **Every time axis with sub-annual data shows months once zoomed in.** Any chart whose x axis is a day-indexed window (the Years-shown slider, zoom/pan) takes its ticks from `lib/time-axis-ticks` (`timeAxisTicks(vs, ve, pw)`), never a hand-rolled year loop: years at full width (every 1, 2, 5 or 10), then every 6, 3, 2 or 1 month as soon as a month gets about 34px, with January printing the year (darker) so the reader keeps their place. Wired into `economy/EconomyChart` and `trade/EraLayers` `YearAxis` (shared by the trade balance, tariff and energy charts). Annual or fiscal-year bar and trajectory charts (immigration, troops, laws, court, demographics, wealth, senate) have no month data, so they keep year labels (10h); a new chart that gains monthly data and a zoom must use the helper.
10i. **Charts bleed into the card padding on phones.** The element that `useElementWidth` measures carries `-mx-3 sm:mx-0`, so below `sm` the plot and its y-gutter extend 12px into the card's side padding instead of leaving white space left of the axis labels. Any new chart inside a padded card does the same. Reference: `troops/TroopsChart`.
10w. **A Sankey turns to run top to bottom on phones, and its labels slant rather than vanish.** Below 720px of plot width the columns become rows. A label that fits across its node sits level; the rest slant up and to the right at 55°: the top row's labels rise from the node's left corner, the bottom row's end at the node's right corner (reaching down-left), the middle row takes whichever side slants less in total. A label steepens only where it would leave the chart, and a neighbour steepens just enough to keep a 14px gap; the label bands grow to fit, so nothing leaves the SVG and the page never scrolls sideways. Wide: labels left of the first column, right of the others (a surface halo, `.sankey-halo`, where they sit over bands), name over value when the node is 28px tall, a name too long for its column shortened with an ellipsis. Hover previews and tap pins a band's or node's card (`useDotCard`; closes on a tap elsewhere, Esc or a scroll) and lights its bands. Reference: the trade product-to-use card that set it was removed (git history, PR #322: `trade/TradeSankeyCard`, `lib/trade-sankey-layout.ts`); the rule stands for the next Sankey.
10p. **Status tiles are the filter and the legend.** A card whose rows carry a status (a bill's furthest step in a committee, an amendment's outcome on a law) opens with a "mono caption + row of tiles": a serif count, the status name, its share, a share bar and a 3px top edge in the status colour. A tile is a toggle button (`aria-pressed`): click filters the list or chart below, click again clears. The tiles recount for any other filter on the card (the amendments card's "Offered by" sponsor select) and keep a 0 tile rather than vanishing; only statuses that occur at all get a tile. Phones: two per row. Each row also names its status in a badge (colour is never the only cue, rule 8). References: `committee/legislation/StageTiles`, `laws/detail/AmendmentsList` (statuses from `lib/law-details-derive` `amendmentStatus`).
10q. **Law page: side-by-side cards size to their content; phones put the date or status first.** On "Who voted for it" the compass and the two party lists share one row from `lg`: each list is only as wide as its longest name (no blank space to its right, names never wrap) and as tall as the compass (`--plot-h`, measured with a `ResizeObserver`), and the compass takes all the remaining width. The Timeline is a `max-h-[32rem]` scroll box; on phones each date is a heading above its actions (repeat dates hidden) so actions use the full width. On phones an amendment's status badge sits above its text (`max-sm:order-first`) so the description and last action are full width. **Header:** the Sponsor and Cosponsors lines share one style (faint "Sponsor: " / "Cosponsors (N): " label, then party dot and linked names). One cosponsor always shows, wrapping if it must; a second joins from `xl`, and "+N others" is the total minus the names shown. From `lg` the passage-vote rows are 12rem wide (17rem below), which moves the divider right. Card order: Summary, Who voted for it, Committees and Related bills (two equal-height cards in one row from `lg`, stacked on phones; Committees goes full width when the law has no Phase 2 record, so no Related card), Timeline, Amendments. Related's list keeps its bounded scroll box so the row stays short. References: `laws/detail/LawVotesCard`, `TimelineList`, `AmendmentsList`.
11c. **Country names are one list, with short forms.** Every page shows a country by `displayCountryName(code, name)` in `lib/trade-names.ts` (trade, ICE removals, green cards and refugees all read it; keyed by ISO alpha-3). The two Congos are named in full, "Democratic Republic of the Congo" and "Republic of the Congo", never "Congo (Kinshasa)". A chart label that cannot fit the full name uses `shortCountryName(code)` ("DRC", "S. Africa", "UAE", "UK"), and only a country with no short form falls back to its three-letter ISO code (ISO has no code that reads "DRC"; `COD` is the standard). Add a short form when its ISO code would read worse; do not abbreviate a short name. The country search matches the short form too, so "drc" finds the DRC. Reference: `refugee-chart.spanLabel`, `trade-country-search`.
11a. **Long row charts (swarm/dumbbell/range lists) never auto-expand on phones.** Below `md` they sit in a fixed-height box sized by **height, not row count**: about 22rem for slim rows (~26px, about 12 rows), about 28rem for chunky rows (~45px, about 10 rows, e.g. the foreign-aid ranked list). Keep it under about two-thirds of a phone screen so the page still scrolls past it. It is `overflow-y-auto` with `overflow-y-auto overscroll-contain touch-scroll`, so a finger drag scrolls the rows inside the card and the page scrolls past it (`.touch-scroll .chart-svg` sets `touch-action: pan-y`). Desktop fills the row height the neighbouring card sets. Give the box `tabIndex={0}` and an `aria-label`. References: `senate/SenateExplorer` ("How each state votes"), `trade/TradePartnersCard`.
11d. **A ranked-row list scrolls its selected row to the centre.** When a filter, dropdown, search or row click selects a state, country, region, product or other row of a long list, the list scrolls so that row sits in the middle of its own scroll box, on first load (from a URL param) and on every later change. It is built into the two shared row charts: `charts/SwarmRows` (dumbbell/range/dot rows: state delegations, trade partners, committees, justices) and `charts/StackedRows` (stacked-bar rankings: immigration, foreign aid, troops, laws, decisions), through `charts/use-scroll-selected` (`useScrollSelectedRow` + `selectedRowsKey`). So a card gets it for free by setting `selected` on the row; mark the row's element `data-selected-row` if you build a new row chart, and call the hook with `selectedRowsKey(rows)`. It scrolls the list's own scroll container only, never `scrollIntoView` and never the page, does nothing when the list isn't scrollable, is instant on first paint and smooth afterwards (instant under reduced motion), and re-centres while the layout settles in the first ~1s. Each page is a cross-section of the other pages clipped to one president's time in office. **No new pipeline:** `lib/president-data.ts` (server-only) reads every number through the loader the matching page already uses (`getLawsList`, `getExecutiveOrdersData`, `getIndicatorObservations` with full history, `getLprPayload`, `getRefugeePayload`, `getImmigrationPageData`, `getEncountersPayload`, `getTradeNational`, `getAidPayload`, `getTroopsPayload`, the energy observations, `getTimelinePayload` for Congress, `court/justices.json` + `getJusticeProfile`); only the portraits and bios are new (`president_bios.json`). Pure, tested shaping in `lib/president-derive.ts` (who gets a page and ordinals, term edges, the day-majority rule for fiscal and calendar years with July–June fiscal years through FY1976, years in office, Congress clipping and both/one/neither days, justices by nomination date with Rehnquist-style elevations) and `lib/president-format.ts` (formats and the generated takeaways); client shapes in `lib/president-types.ts`; URLs in `lib/president-url.ts`.

- **Who gets a page:** Truman on (`FIRST_PAGE_START`): earlier terms would be mostly empty cards. One page per person; Trump's two terms are two segments on every chart (a 14px gap between them) and two start→end readings.
- **Order:** header laid out like the member and justice headers ("President" kicker, name, ordinal · party, dates beside the portrait; the Wikipedia lead in an About column to the right from `lg`; previous / next president (surnames) and All presidents under the identity block, before About; no `PageHeader`; the "conditions, not a scorecard" caveat sits at the foot of the page), three count tiles (in office, major laws signed, justices appointed; one row at every width), then themed rows (rule 10r row labels): Who held power (Congress control | Supreme Court appointments), Laws (owner decision 2026-10-20: two full-width cards, "Landmark laws and cases" then "Laws signed", which holds the yearly bars and policy areas beside the major-laws list, so the count and the list behind it read as one; before 1973 only the list; `MAJOR_LIST_NOTE` under the list says how major laws differ from the landmark card), Economy (Misery index | Deficit and debt), Immigration (Green cards and refugees | Removals and border encounters), The U.S. and the world (Goods trade balance | Foreign aid), Security and energy (Troops abroad | SPR), then Executive orders in its own row at the bottom (one full-width card, from 1994).
- **Colour:** one hue per row, never grey bars. Economy `--prez-econ`, Immigration `--prez-immig`, The U.S. and the world `--prez-world`, Security and energy `--prez-security` (bars and single lines alike; the misery card keeps its two-line colours; tokens in `globals.css`, held to 3:1 by `validate_palette.js` `PREZ_KEYS`). Laws signed and Executive orders are the exception: their bars are **stacked by policy area / topic** (`SeriesPanel.stack`, `SeriesPoint.stack`, built by `stackedYears` in `lib/president-data.ts`), in the same colours as the "By policy area" / "By topic" list under them, which doubles as the legend (no second legend). Tooltips list the layers, largest first; the table view gains one column per layer.
- **Missing data:** a panel with no value in the term is dropped; a card with no panels is dropped and its partner spans the row (`wide`); a row with neither is dropped. A panel whose series starts after the inauguration says "Data starts …" under its caption.
- **Cards** (`PresidentCards.tsx`): `CardShell` is a four-track subgrid (title, takeaway, body, notes row) shared by the pair. `TermSeriesChart` draws a line (monthly, quarterly, weekly) or bars at 72% of a year (fiscal years, years in office) per term, y labels in a gutter, peak and low labels (above the bar end for bars), the president's term band under the axis (not tappable: the page has no window), hatched preliminary bars, sticky tap tooltips. A card with fewer panels than its partner gets taller plots so the pair ends level. Every panel shows "first → last" readings at the right of its caption.
- **Congress card details:** a Congress that convened **less than 30 days before a finished term ended** (`MIN_CONGRESS_DAYS` in `lib/president-derive.ts`; the 17 lame-duck days of the next Congress when a president leaves in January) is left out of the rows **and** of the days that feed the takeaway and the directory's "Congress on their side" bar, so nothing says "neither for 1 months". The ongoing term is exempt. On phones (below `sm`) each Congress label sits on its own line above its two chips (`grid-cols-2`, chips `h-full whitespace-nowrap`), so House and Senate chips are the same size in every row and no title wraps; from `sm` it is the three-column row. The card's last paragraph (seats at the start of each Congress, independents counted) is not repeated above the Data notes, which already say it; only the "*" note shows, when a Senate majority changed hands.
- **Copy:** takeaways are generated from the drawn values (`panelTakeaway`: first and last reading, plus an inner high or low) and never give a cause; the page-level "How to read this" says the numbers are conditions during a presidency, not a scorecard. Methodology lives in each card's Data notes (`components/presidents/notes.tsx`). Mayhew is not named on these pages ("major laws", "important enactments"); the Laws page explains the list. The major-laws list shows each law's CRS sentence and its House and Senate passage votes (`tallyText`, as on the Laws page).
- **Explore links:** each card ends its notes row with a quiet right-aligned link to the page its data comes from (`MORE` in `notes.tsx`: "Economy →", "All laws →"), so Data notes no longer repeat "More on the … page".
- **Major-law summaries** (`lib/mayhew-note.ts`, `mayhewDescription` in `president-data.ts`): the Laws page's one-line summary is the CRS first sentence only when it is one finished sentence of 40-300 characters, so omnibus acts (and the 103rd-105th Congresses) have none. On the president page those fall back to Mayhew's own entry for the law (`quote` in `reference/mayhew-major-laws.json`), trimmed, never reworded: month/year notes, veto notes and a label that only repeats the law's title go; a capitalised label with nothing after it gives no summary; a provision of a bigger law reads "Includes: ...". 133 of the 142 major laws without a CRS sentence get one. The Laws page itself is unchanged.
- **Landmark laws and cases card** (`PresidentTimelineCard.tsx`, owner decision 2026-10-20: leads the Laws row, ahead of the Laws signed card, whose major-laws list stays the full list behind the directory's count): the Timeline page's `PowerChart` for this president's years, a fixed window with no zoom (`minYear` = `maxYear` = the window, `startIso` / `endIso` clip it to the first and last day in office), Court by median lean, over every Timeline event in a term (Trump's two terms show the gap between them, markers only in his terms), then the same events newest first with each law's House and Senate totals (`TlEvent.tally`; "No roll call" where a chamber passed it without one) or the case's vote and author. A number on a row opens the marker's note on the chart; a marker keeps its Timeline number. `getPresidentPage` passes the whole `TimelinePayload` (about 45 KB) plus the window and event numbers (`PresidentTimeline`); null before the Timeline starts (4 March 1933). Presidents' landmark picks live in `timeline-events.json`, so a president with few laws there shows a short card: add events there, with their votes in `early-law-votes.json` before 1973.
- **Directory columns** (`PresidentsDirectory.tsx`, `JusticeFaces.tsx`; owner decision 2026-10-19, raw counts of laws and orders replaced because a third of Reagan's laws are commemorations): **Major laws** (`laws.major`, Mayhew list; "incl." names the law the president is best known for via `majorTopFor`: the editorial pick in `pipeline/reference/signature-laws.json` (owner decision 2026-10-20: Mayhew's capitals favoured reconciliation acts nobody ties to a president; picks must be on the president's list and a test checks they match), falling back to the first capitals entry before 1973, then `biggestMajorLaw` (a law alone in its capitals entry in `laws_major.json`, then one in a shared capitals entry, then the earliest signed); pre-1973 a dash "data from 1973", Nixon "from 1973", Trump "later term not yet assessed"), **Congress on their side** (a thin bar of `congressSummary.days`: party colour = both chambers, a tint = one, grey = neither; label from `controlLabel`, e.g. "Both chambers, 2 of 8 years" / "One chamber, 6 of 8 years" / "Neither chamber, 4 years" (the chamber count always comes first; the president card uses the same wording); the key is a hover/focus tooltip on the column header from `md` up (`HeadTip`), and a legend row above the list on phones, which have no headers), **Justices appointed** as 24×30px faces (elevations left out; a dot marks a justice still serving; a tap or click pins a name card with the only profile link, rule 10t), **Misery, in → out** (sparkline of the page's misery panel from `sparkPaths` with first and last reading, md and up only: the line is unreadable at phone width and the card on a phone already carries four columns; header and Data notes say these are conditions during the term, not effects). Executive orders left the directory; they stay on each president's page. Rows are one stretched link, so the faces sit above it (`z-10`).

### Timeline page (`components/timeline/`, `lib/timeline-*.ts`, `/timeline`)

The one page that spans all three branches, so it sits outside `lib/verticals.ts`: `CROSS_BRANCH_PAGES` (`lib/site-info.ts`) gives `SiteNav` a neutral tab after the branch tabs (ink underline, never a branch colour; no `BranchTheme`, so the default accent), `SiteHeader` a plain wordmark, and `sitemap.ts` an entry. Everything that reads the Court (the one-party strip, tiles, era list, notes, tooltip, table) follows the Court-by switch: `lean` (median Martin-Quinn score; |score| < 0.15 is the centre; no score before October 1937) or `appt` (appointing party of the sitting majority; a tie is even). Pure logic and its tests: `lib/timeline-derive.ts` / `.test.ts` (state at a date, vacancy rule, change points, spans, eras, status names, tile counts, years by status, search matching, marker binning). The chart is hand-drawn SVG measured with `useElementWidth`, bleeding into the card padding on phones (rule 10i), with `timeAxisTicks` (months once zoomed, rule 10i) and `fitTermLabel` on the president row (rule 10c, "Bush 41"/"Bush 43" where room allows). `PowerChart` also has a `compact` mode (strip + President/Senate/House only, no Court row, the strip counts Congress alone, a `startIso` window start, no zoom/pan, a tap on a president opens the `presCard` prop instead of zooming) used by the Presidents directory, so both pages draw the same rows, labels, colours and `fitTermLabel` shortening; `chamberYears` (`lib/timeline-derive.ts`) gives the years a president's party held both chambers, one or neither. Era list and table run newest first (rule 15a). Status tiles are three across at every width (the phone two-per-row of rule 10p would leave a lone tile; `StageTiles` also puts three on a phone row). Linked from the homepage (`HomeTimelineCard`, fourth card), from the page-shortcuts row of Laws and Decisions ("See who held power, 1933–now →"), from the site search (`CROSS_BRANCH_PAGES`), the About questions list and a Timeline entry in `lib/methodology-content.ts` (shared group, `docs/TIMELINE_METHODOLOGY.md`).

### Public API and MCP (`lib/api-*.ts`, `lib/mcp-server.ts`, `app/api/v1/`, `app/mcp/`, `/api`)

One registry, three surfaces. `lib/api-datasets.ts` lists the published tables (id, title, grain, units, sources, optional `license`, `fieldNotes`, a `load()` over `pipeline/output/`); the REST routes, the OpenAPI document, the MCP tools and the catalog on `/api` all read it. `lib/api-query.ts` is the pure filter/sort/page/CSV engine (tested); `lib/api-service.ts` shapes what both REST and MCP return, so they cannot disagree.

- **Adding a dataset:** add a `DEFS` entry with units, sources and any source terms (`license`) copied from `docs/CREDITS.md`; nothing else. Ids are never renamed. Response shapes only gain fields (`v1`).
- **Not published, on purpose:** Wikipedia-derived text (CC BY-SA: bios, case summaries, landmark lists), photos, `law_details/`, `law_votes/`, `committee_bills/`, `line-items/` and `court/justice_votes.json` (coded tuples). Revisit before exposing any of them.
- **Terms stay with the data.** Every REST body and MCP result carries `attribution`, `sources` and `license`. A source whose licence restricts use (SCDB CC BY-NC; troopdata GPL-3.0) must say so in `license`, in the registry, before it is added.
- **New routes that load tables by name need an `outputFileTracingIncludes` entry** (`API_TABLES` in `next.config.ts`), including the per-year `trade_by_country/` and `duties_by_country/` shards. `pipeline/output/trade_products/` (and `trade_enduse/`, read by `/data/trade/enduse/[code]`; `trade_product_use/` is excluded the same way until a route reads it) is the opposite case: only the static `/data/trade/products/[code]` route and the trade page's build read it, so no server function needs it and `outputFileTracingExcludes` keeps it out of every one (loaders that read `pipeline/output/` by a computed name otherwise pull in the whole directory, and the extra 12 MB split the bundles past the Vercel Hobby plan's 12-function limit). A non-static route that reads it must drop that exclude and list itself in the includes. Never read a file through a fully spread path (`join(process.cwd(), ...parts)`): it traces the whole project.
- No auth and no rate limit yet (the contact form's per-instance limiter is the only one in the repo). If traffic needs one, use a Vercel Firewall rule on `/api/v1/*` and `/mcp`.

### Demographics page (`components/demographics/`, `lib/demographics-*.ts`, `/congress/demographics`)

Data: `legislators.json` + `terms.json` + presidents -> `lib/demographics-data.ts` -> pure `lib/demographics-derive.ts` -> `DemographicsPayload` (`lib/demographics-types.ts`). Decisions (recorded so they aren't re-litigated):

- **Roster = everyone who held a voting seat at any time in the Congress, not who was seated on day one.** The source's term dates are nominal Congress-length ranges for almost everyone before the 1990s (a mid-term replacement and the member they replaced both read the whole Congress), so a first-day roster can't be rebuilt without guessing (`docs/DEMOGRAPHICS_PREFLIGHT.md`). The page says so in its Data notes. Ages are counted on the convening day (`CONVENING` in `lib/demographics-entities.ts`; the day the Congress actually convened, not Jan 3).
- **Slots and window.** One slot per Congress; a Congress is drawn when its convening year is in the years window (`windowRows`). The slider's term segments span the Congresses each president held most of (`bandTerms`), so they never overlap. The president for a slot is the one in office for most of the Congress (`presidentForCongress`: most days between its convening day and the next one's), so a Congress convening Jan 3 of an inauguration year goes to the incoming president.
- **Palette.** `--tenure-1..4` (four steps of the accent, lightest = first Congress) are validated in `validate_palette.js` (`TENURE_KEYS`, all pairs forced, >= 3:1 on every surface); they are darker than a pale-to-dark mock would be because the lightest step must clear 3:1 against the card surface in both themes.
- **No legend on the tenure chart** (share only, per the page spec), so it follows the party pick but cannot set it. The women legend toggles the page's party pick (it no longer switches the chart to the count view or clears on Share: with a party picked, Share of all is that party's women and men as a share of its own members).
- Out of scope, deliberately not built: race/ethnicity, religion, military service, occupation, education (not in `congress-legislators`), a state filter, ideology cross-over, history before 1933, per-member pages (list rows link only to the 119th's profile pages).
- **Each card ends with a member list for one Congress** (`MemberList`, above the Data notes row): the pinned Congress, else the latest one *in the years shown* (never the latest of all, so a 1945-1978 window defaults to the 95th), in the chamber view. The stat strip uses the same rule (`readoutRow(rows, livePin)`; it used to fall back to the latest overall and so disagreed with the charts under a narrowed window). The list is one Congress, never everyone who served in the window: an age or a tenure needs a reference Congress, and a window-wide list would match no number on a chart. The header has ‹ › to step the pin through the Congresses shown (clamped to the window), a reverse-order button and a `ListSearch`, with the Congress, order and count on a line under them. **Party is a page-level pick, not a per-list control**: a `<select>` in the pinned bar (`DemographicsFilterBar`: All parties / Democrats / Republicans / Other parties, on the Chamber row on phones too) and every party legend set one state (`DemographicsPageClient` `party`). It *filters*, never highlights (rule 4): the Age lines (Other gets a grey line only while picked), the Women stack and Share-of-party lines (the dashed all-members line stays as a reference and is a plain legend item), the Tenure bars (each bar 100% of that party's members, from `DemoCongress.tenureBy` / `servedBy` / `age.O`; `sliceOf` in `lib/demographics-chart.ts`), the stat strip and all three lists. Readouts name the party. "Other parties" is listed only while the Congress shown (the pinned one, else the latest in the years shown) has such a member (early minor parties, independents who caucus with neither party), the same way the Age chart draws only the Democratic and Republican lines; a pick of it that the Congress shown no longer supports is not applied and comes back when a Congress that has them is shown again, like a pin that has left the window. From `md` up each row also carries the other cards' figures (Age list: birth year and first year; Tenure and Women lists: age and first year), so the gap beside the name carries data; phones drop them. Rows are numbered by place in the full ordering (a name search keeps its rank), in the `MemberNeighborList` scroll-box shape (`h-[18rem]`, `overscroll-contain`, rule 11a). Age card: oldest first, age on the convening day (no birthdate sorts last as "n/a"). Women card: women only, longest-serving first. Tenure card: everyone, longest-serving first; no band filter. Tenure ties go to the earlier first Congress, then A-Z by surname (`sortMembers`). Years are Congresses x 2, counting the listed Congress, the same as the tenure chart. The list's count is the chart's seat count (a test checks every Congress and view against seats, women, tenure bands, servedSum and median age). Only members of the latest Congress have a profile page (`hasProfilePage` rule), so older rows are plain text; a photo gutter is kept whenever any row in the list has a face, so names line up.

## Divergences: session prompt / mockups vs. the real code

The committees session prompt (`committees-feature-session-prompt.md`) and its
two HTML mockups were written without repo access. Where they differed from what
was actually here, and how it was resolved:

1. **The prompt's cited source docs don't exist.**
   `congress-ideology-requirements.md`, `TECHNICAL-REQUIREMENTS.md`, and
   `ARCHITECTURE_MAP.md` are not in the tree or git history. Anything the prompt
   attributes to them is unverified — in particular the "~320px capped list"
   figure (see #2). This file is the `ARCHITECTURE_MAP.md` the prompt expected,
   created now.

2. **Card-height / whitespace guidance was already superseded.** The prompt
   says "stop trying to match the two cards' heights… cap the tall list at a
   fixed scrollable height (~320px)… no cross-card coupling." But `main` had

   page's own precedent (`MemberIdeologySection`), not a height-matching
   mechanism.

3. **`CompassChart` couldn't take committees as-is.** It was hard-typed to
   `ChamberMember` (used `bioguideId`, `lastName`, `partyCode`, `isCurrent`,
   `<MemberTooltip>`, `memberPath`). Per the prompt's own "call it out for a
   human decision" tenet, this was flagged; the chosen fix was to **extract the
   pure scatter into `charts/ScatterPlot`** (and the delegation row list into
   `charts/SwarmRows`) and make the member and committee charts thin wrappers.
   `DelegationChart` keeps its full public API and pair/range/`filterState`
   behaviour — verified unchanged in a browser.

4. **Committee identifier.** The prompt wanted the route
   `/congress/committees/[thomas_id]/…` and data keyed by `thomas_id`. The
   existing `lib/types.ts` stub and DATA_CONVENTIONS §1's "not `thomas`, not a
   synthetic slug-as-key" language both point the other way, so the field and
   route param are **`committee_id`** (holding the THOMAS id value, e.g. `HSJU`).

5. **No `--joint` colour token.** The mockups used one; the real palette

6. **Latest-Congress gate, not a hardcoded 119.** The prompt says "119th"
   throughout; the code derives the latest Congress from the data
   (`committeesLatestCongress()` / `getChamberCurrent().latestCongress`) and
   gates the toggle to that, matching the rest of the app.

7. **Committee search is a small sibling component, not a generalisation of
   `SenatorSearch`.** Search isn't one of the shared chart primitives the
   tenet is about, and the member combobox's a11y is delicate;
   `components/committee/CommitteeSearch` mirrors its chrome for committees.

8. **Long committee names.** Real short names run to

9. **Assorted mockup chrome** (a `WEALTH SOON` nav done differently, an

## Net worth track — Sessions 1–7

Built from `net-worth-claude-code-plan.md`, seven sessions. Notes on where
the plan and the shipped code diverge, beyond what's already called out
inline in the tables above:

1. **`/congress/wealth`** is a section of the Congress vertical (it shipped at `/wealth` originally; `/wealth` now 308s).
2. **The party wealth chart was built (Session 3) then explicitly removed**
   on direct request, along with tightened list headers — a real, shipped
   feature taken back out, not a divergence in the "prompt vs. code"
   sense. `/congress/wealth` today is: filter bar, scatter, highest/lowest lists.
3. **Session 5 (line-item extraction) ran at full scale, not just the
   session's own investigate-phase sample.** The plan's Session 6 depends on
   Session 5's *output existing*; validating that against only the ~85
   locally cached House PDFs and calling it done would have left Session 6
   built against a near-empty `line-items/` directory. Session 5 fetched the
   ~2,600 remaining House PDFs from the House Clerk's own site (all already
   publicly available, same one-PDF-per-request pattern `build.py` already
   uses) before Session 6 started — 3,507 of 3,515 usable filings
   reconciled. See `docs/NET_WORTH_METHODOLOGY.md`'s "Line items and the
   profile card" section for the numbers and the reconciliation gate.
4. **No click-to-select-driving-a-dropdown pattern existed before Session
   6** — checked `senate/SenatorTrajectoryChart` (no click handler at all)
   and the wealth scatter's own `selectedId` (highlights a marker, doesn't
   drive another control). Built from scratch for `wealth/MemberNetWorthChart`
   + `wealth/MemberWealthItemsPanel`, modeled structurally on
   `SenatorTrajectoryChart`'s `ChartFrame`/`Axis`/zoom-to-data-y-domain shape.
5. **The profile card's chart x-axis and gap labels needed a second pass**
   (reported directly, not found in review): the plan says "one point per
   year covered," which a first cut read as "always plot the full
   2013–2025 window" — for a member who entered Congress well after 2013,
   or whose data starts later, that left a long empty run-up. Fixed to start
   at the member's own first reported year instead. A related bug in that
   same first cut rendered one muted gap label *per missing year* rather
   than one per contiguous run — for a multi-year gap this stacked several
   "no filing" strings on top of each other into unreadable text
   (`"no filing filing filing"`). Both fixed in `MemberNetWorthChart.tsx`.
6. **A real data-quality bug, exposed (not caused) by removing the item
   list's old single-line truncation**: some House PDF vintages' embedded
   fonts map certain glyphs — confirmed on the "L" of "LOCATION:" and the
   "D" of "DESCRIPTION:" continuation labels — to literal NUL/control
   codepoints, which pdfplumber decodes as-is rather than dropping. Hidden
   behind a `truncate` (single-line ellipsis) UI treatment on the shipped-
   then-immediately-revised item list, this only became visible once the
   list was widened and given room to show full descriptions. Fixed at the
   word-collection point in `house_line_items.py` (`_clean_word`), scoped to
   that module rather than `extract_text.py` (shared with the trusted,
   untouched `columns.py` band-counting path).
7. **The item list's remaining known display artifact**: on rare pages with
   several same-band items back-to-back, one item's description can still
   absorb a neighbor's text (the reconciliation gate only guarantees band
   *totals* match, not that every description is paired with its own value
   — documented residual risk since Session 5, see `house_line_items.py`'s
   module docstring). Mitigated in the UI with a 3-line clamp rather than
   chased further at the extraction layer in this pass.
8. **Assets/Liabilities is a toggle, not two stacked sections.** The
   original Session 6 build listed both under sticky "Assets · N items" /
   "Liabilities · N items" headers in one scrollable region — functional,
   but on a member with 300+ assets, liabilities were scrolled out of
   reach. Revised to a two-way pill toggle (same `role="group"` pattern as
   `ChamberSwitch`) that replaces the panel's title, one list shown at a
   time.

## Session: Supreme Court landing page (`/supreme-court`)

Data: `lib/justice-data.ts` (server-only, cached) reads the four `court/*.json` outputs and calls the pure `lib/court-derive.ts` (`buildCourtPayload`) to produce one compact `CourtPayload` (`lib/court-types.ts`, client-safe: per-justice score/interval arrays by term, per-term court record incl. mid-term left/joined, presidents in office order, the fitted score domain). `getCourtHubSummary()` feeds the hub card. Rules (a/b median, domain, turnover, presidents) are in `docs/SCOTUS_DATA_METHODOLOGY.md`.

Components (`components/court/`): `CourtExplorer` (state, cards, `<details>` table fallbacks), `CourtToolbar`, `JusticeSearch` (lives in chart 1's card), `JusticeStrip` (chart 1), `PresidentRows` (chart 2), `JusticeTrajectory` (chart 3), `CourtHubSparkline`.

Which primitive carries which chart:

- **Chart 1** `JusticeStrip`: `ChartFrame` + `Tooltip`; geometry is `lib/court-strip-layout.ts` (deterministic beeswarm dodge + label placement; pure, so `court-strip-layout.test.ts` audits every real term at six widths). `ScatterPlot`/`SwarmRows` don't fit a dodged single-axis strip with placed labels, so the smallest new thing is the layout function, not a parallel chart stack. Fixed pixel height (`STRIP_GEOMETRY`) so the card never resizes while playing; a 12.5px IBM Plex Sans label box is 16.5px tall (measured), and the layout is built on that.
- **Chart 2** `PresidentRows`: `SwarmRows`, extended with optional `domain`, `showAxis`, and per-point `radius`/`opacity`/`ring` and per-row `tinted`/`faded`. All default to the Congress behaviour, so `DelegationChart`/`CommitteeSwarm` are unchanged. Card-height mechanism is `SenateExplorer`'s (grid `md:items-stretch`, list absolutely positioned in a `flex-1` wrapper at md+; below md it expands).
- **Chart 3** `JusticeTrajectory`: `ChartFrame` + `Axis` (years) + `Tooltip`; playhead and click-to-scrub follow `TrendChart`; legend at the bottom.

Reserved heights: the "Mid-term change" line and the selected-justice row always occupy their space so chart 1's card (and chart 2's stretched card) never change height with the term.

Config/plumbing: `lib/verticals.ts` Court `status: 'live'`; `app/sitemap.ts` already emits every live branch, so `/supreme-court` is in it; `next.config.ts` `outputFileTracingIncludes` has `/supreme-court` and `/` keys for `./pipeline/output/court/*.json`.

### Member profile: subcommittee seats

`CommitteeMembershipsCard` nests a member's subcommittee seats under each parent committee row in a native `<details>` ("N subcommittees ▸"), collapsed by default. Plain text only (name, role tag, member count): no blended-position strip, since subcommittee rosters are too small for a meaningful mean. Data: `MemberCommitteeMembership.subcommittees` from `lib/committee-data.ts`.

### Committee seals and descriptions

`committee/CommitteeSeal` is the one committee mark, used beside every committee name that is a list row or a heading: the committee page title (88px), the member profile's Committee memberships rows (28px), the law page's Committees card (28px), `CommitteeNeighborList` and `CommitteeSearch` (20px). House and Senate use the public-domain seals from Wikimedia Commons, saved as 192px PNGs in `public/images/seals/house.png` and `senate.png`; a joint committee uses the site's own drawn "Joint Committee" seal (navy ring, gold rule, Capitol dome; the ring lettering is dropped under 40px). Desktop only: the seal is `max-sm:hidden` everywhere, so phones show names alone (the Committee memberships card keeps its two-column name / alignment-track rows on mobile). Always decorative (`alt=""`): the name is beside it. Not added to chart axes, tooltips or the swarm / compass labels, where a mark would crowd the label (rule 10).

The About block reads `committee_summaries.json` (`fetch/wikipedia-committees.ts`, `pnpm fetch:wikipedia-committees`, refreshed with the member bios by `wikipedia-freshness.yml`). It uses the article's whole lead (not the REST summary, which is often one bare sentence): the first sentence, then up to two more that say what the committee does, never reworded; sentences naming the chair or counting members, and trivia, are left out (`wikipedia/committee-lead.ts`, tested). A committee whose lead never says what it does, or with no article (8 of 49, including the 119th's January 6 select subcommittee), gets a one-line summary written for this site (`WRITTEN` in the fetch script, `source: "written"`, credited as written by InsideGov; a Wikipedia edit that adds the jurisdiction takes over automatically). Article titles: "United States " + the committee's name, with overrides in `TITLE_OVERRIDES`.

### Analytics, sitemap dates and structured data

- **Events:** call `track()` from `lib/analytics.ts` (typed by `AnalyticsEvents`), never `@vercel/analytics` directly. The shared chart controls already report `filter_change` (PillGroup, PartyFilter, MultiSelectFilter, SortToggle, RangeSelector), `chart_zoom` (ZoomControls, `use-zoom-pan`) and `chart_pin` (PinReadout); `OutboundLinkTracker` in the layout reports every external link click. A new control built from those parts is tracked for free; a bespoke one should call `track()` itself. Bursts (drags, wheel spins) pass a `throttleMs`.
- **Sitemap dates:** `lastModified` comes from `lib/data-freshness.ts` (pipeline reports), never `new Date()`. A new vertical's data source goes in there.
- **JSON-LD:** builders live in `lib/structured-data.ts`; a new topic page gets a `TOPICS` entry (its Methodology entry ids and first date) plus `<TopicDatasetLd path=... />`. See `docs/launch-checklist.md`.
